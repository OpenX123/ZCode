# 1.5.1：1.5.0 回归修复 + YCode 改名（已与用户确认）

来源：2026-11-22 用户在 1.5.0 实机截图反馈与追问。所有决策已确认。

## 工作包 E：1.5.0 UI 回归

1. **Claude 入口不显示模型名**（已确认）：`packages/ui/src/external-engine/EngineControls.tsx:132-137` 的 W1 规则在模型为 `default` 别名时只显示档位。改为始终“模型 档位”（如 `Opus 5.5 Med`）；`default` 能从 description 解析出真实模型名时用真实名，否则显示 `Auto`（悬停/无障碍说明“默认模型”）。同步 `docs/desktop/external-agent-engines-spec.md` 与测试。
2. **无响应提示条左侧未对齐**（已确认）：`ConversationTimeline.tsx` `data-v4-live-tail-footer` 容器只有 `pb-2`，缺少轮内容的水平内边距。与轮内容同一左边线。
3. **工具执行中重复提示**（已确认，设计调整）：`running_tool` 不再单独显示提示条；改为在正在运行的那一行工具行尾追加耗时（如 `正在执行 curl … · 1 分钟`，≥60s 才显示）。独立提示条只用于 `waiting_model` 无输出（60s hint / 5min warning 不变）。更新 `docs/chat/turn-stall-indicator.md`。
4. **提示用原始工具名 `Bash`**（已确认）：如仍需显示工具名，复用工具行已有的显示名映射（“终端”等）。
5. **Composer 停止按钮左侧出现空心转圈**（待查）：先定位来源（疑似上下文用量指示或新增状态），判定是否 1.5.0 回归，再修正。
6. **default 模型名解析失败时的显示**（待查）：检查本机 Claude adapter 实际返回的 `default` 条目 description（`claude-agent-acp` session-model `buildModelConfigOption`），保证常见形态能解析出 `Opus 5.5` / `Fable 5.2` 等名称。

## 工作包 G：数据目录 ~/.ycode + 环境变量 YCODE_* + 远程目录

- **本机迁移（唯一所有者：desktop main 启动早期，先于任何子进程启动与 `setting.json` 读取）**：
  - 条件：`~/.zcode` 存在且为真实目录、`~/.ycode` 不存在、无其他 YCode/CLI 进程占用（Windows 上以 rename 是否成功为准，失败即跳过）。
  - 动作：`rename(~/.zcode, ~/.ycode)`，然后在 `~/.zcode` 创建指向 `~/.ycode` 的链接（Windows 目录联接 junction，mac/Linux symlink），保证写死旧路径的代码、旧 CLI、降级到 1.5.0 仍可工作。
  - 任一步失败：回滚或保持旧目录可用，继续使用 `~/.zcode`，写 `warn` 日志；不得出现两份数据。
  - 自定义 `dataBaseDir`：对 `<dataBaseDir>/.zcode` 适用同样规则（`~/.zcode/v2/setting.json` 位于 home 下，先迁移 home）。
  - `ZCODE_DATA_BASE_DIR` 等 dev 隔离目录（如 `~/.zcode-dev-home`）不迁移。
- **路径解析改为 `.ycode`**：`packages/services/src/paths.ts` 及其直接使用方、`desktopDataBaseDirBootstrap.ts` 等硬编码 `homedir()/.zcode/v2/setting.json` 的位置、CLI 默认 `storage.dir`（`apps/zcode-cli/packages/contracts/src/config/index.ts`）、`.zcode-beta` → `.ycode-beta`（同样迁移+链接）、server CLI `runtime/paths.ts`。优先收敛到少数 helper（解析顺序：新目录存在 → `.ycode`；仅旧目录存在且未迁移 → `.zcode`），其余写死 `.zcode` 的位置通过链接继续工作，能顺手改为 helper 的就改。
- **环境变量**：为用户可配置的路径/模式类变量增加 `YCODE_*` 名称并优先读取，旧 `ZCODE_*` 继续生效：`DATA_BASE_DIR`、`STORAGE_DIR`、`SESSION_DB_PATH`、`HOME`、`BETA`/`ENV`、`DESKTOP_HOME_DIR`、`DESKTOP_USER_DATA_DIR`、`DESKTOP_SESSION_DATA_DIR`、`SERVER_RUNTIME_ROOT`。用一个共享读取 helper，进程间内部传递的变量（如 `ZCODE_VERSION`）不改。
- **远程**：`REMOTE_BASE` 等改为 `~/.ycode/server`（`deployShared.ts`、`connect.ts`、`zcodeAgentBundleWrapper.ts`、`source-server/transportAdapter.ts`、`sourceServerProbe.ts`、远程同步路径）。部署时：若远程存在 `~/.zcode` 且无 `~/.ycode`，停止旧 daemon → `mv ~/.zcode ~/.ycode` → `ln -s ~/.ycode ~/.zcode` → 启动新 daemon。用户很少用远程，不做双路径并行。
- **不改**：appId `dev.zcode.app`、Electron userData `AppData/ZCode*`、工作区内项目级 `.zcode/` 目录、`@zcode/*` 包名、协议字段名。
- 新增 spec `docs/desktop/ycode-data-dir-migration.md`（含所有者与事件顺序图、失败回滚、验收场景）。
